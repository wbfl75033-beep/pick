# 발주처 확인 필요 사항

설계서·SQL과 실제 index.html 코드를 대조하면서 나온 불일치입니다.
작업 자체는 진행 가능하며, 아래 항목은 **결정만 받으면 됩니다.**

---

### 1. 줌 강좌 접속 정보 4개 (우선순위 높음)

`savePoster()` 는 `zoomLink / zoomId / zoomPw / zoomNote` 를 저장하는데
제공된 SQL의 `posters` 테이블에 해당 컬럼이 없습니다.

- 현재 처리: `db/schema.sql` 에 `zoom_link, zoom_id, zoom_pw, zoom_note` 컬럼을 **추가해 둠**
- 확인 필요: ① 기능 유지 → 그대로 진행 / ② 기능 삭제 → 컬럼과 입력칸 제거
- 참고: 화면 코드상 줌 입력칸은 현재 `hidden` 처리되어 있어 의도가 불분명합니다.
- 보안 참고: 유지한다면 **줌 비밀번호가 비로그인 방문자에게도 그대로 노출**됩니다.
  신청자에게만 공개하려면 공개 뷰를 따로 두어야 합니다. (schema.sql 에 주석으로 준비)

### 2. 강사 구분값 매핑

| 위치 | 값 |
|---|---|
| 기존 데이터 | `type: "추천"` / `"제휴"` |
| 관리자 등록 폼 | `specialTag: "추천강사"` / `"제휴강사"` / `"none"` |
| DB 제약 | `'추천'`, `'제휴'` **둘만 허용** |

→ `"none"`(구분 없음)으로 저장하면 **에러가 납니다.**
- 확인: `none` 선택지를 없앨지, 아니면 기본값 `추천`으로 저장할지

### 3. 관리자 폼에 입력칸이 없는 필드 4개

DB에는 있는데 등록 화면에 칸이 없습니다.

- `phone_private` — 관리자 전용 연락처 (설계서의 핵심 기능인데 입력 방법이 없음)
- `email` — 강사 이메일
- `is_visible` — 노출/숨김 토글
- `sort_order` — 노출 순서

→ 입력칸을 추가할지 확인 필요. **최소한 `phone_private` 는 추가해야 설계 의도대로 동작합니다.**

### 4. 삭제 방식

- 설계서: "삭제 대신 `is_visible` 로 숨김 처리"
- 현재 코드: 목록에서 실제로 제거
- 현재 처리: `js/config.js` 의 `SOFT_DELETE: true` (숨김 처리) 로 세팅
- 확인: 완전 삭제를 원하면 `false` 로 변경

### 5. 상단 고정(핀) 기능의 성격

- 현재 코드: 방문자 브라우저 `localStorage` 에 저장 (개인 설정)
- DB: `instructors.is_pinned` 컬럼 존재 (전체 공통 설정)
- 확인: ① 관리자가 정하고 모든 방문자에게 동일 / ② 방문자 개인 설정
- 참고: 찜하기(하트)는 로그인이 없으므로 `localStorage` 유지가 맞습니다.

### 6. 노출 순서 변경 기능

요청서에 "순서변경 버튼 숨김"이라 적혀 있는데 **코드에 순서변경 기능이 없습니다.**
(1211행에 주석만 있고 함수 없음)

- 확인: 신규 개발이 필요한 항목인지, 요청서 착오인지
- 신규 개발이면 별도 공수로 산정 (`PickDB.saveOrder()` 는 미리 만들어 둠)
