## 1. 의뢰 범위 — 딱 이것만

### 지금 상태 (문제)

관리자로 로그인해서 **관리자 설정**에서 강사·공고·광고·배너를 등록·수정·삭제하면,
**화면에만 바뀌고 새로고침하면 전부 사라집니다.** 사진을 올려도 마찬가지입니다.

DB에 저장하는 코드가 아직 연결되지 않았기 때문입니다.

### 만들어야 할 상태 (목표)

**① 관리자 설정에서 한 작업이 실제로 저장되고, 화면에 바로 반영될 것**

```
관리자 설정에서 등록/수정/삭제
   ↓
Supabase DB에 저장
   ↓
화면 목록이 즉시 갱신 (새로고침해도 그대로)
```

**② 사진·파일을 넣으면 Supabase Storage에 자동 저장될 것**

```
파일 선택
   ↓
Supabase Storage 에 자동 업로드
   ↓
저장된 주소가 DB에 기록되어 화면에 표시
```

### 손대지 않아도 되는 것 — 전부 완료됨

| 항목 | 상태 |

| 기존 데이터 이관 (강사21·영상63·공고2·배너2·광고3) | ✅ 완료 |

| 관리자 로그인 / 비로그인 시 버튼 숨김 / 서버 권한 검증 | ✅ 완료 |

## 3. 시작 전 결정 3가지

저장 기능이 직접 건드리는 지점이라, **먼저 정하지 않으면 두 번 일하게 됩니다.**
발주처에 문의하되, 답이 늦으면 아래 기본값으로 진행하고 기록해두세요.

### ① 강사 구분값 — 이대로 두면 저장 시 에러가 납니다

| 위치 | 값 |
|---|---|
| 관리자 등록 폼 | `추천강사` / `제휴강사` / **`구분없음(none)`** |
| DB 제약 | `추천`, `제휴` **둘만 허용** |

`구분없음`을 고르고 저장하면 **DB 제약 위반 에러**가 발생합니다.

**기본값 제안:** `구분없음` 선택지를 없애거나, 선택 시 `추천` 으로 저장

### ② 관리자 전용 연락처 입력칸이 없습니다

발주처 `DB설계서` 2장의 핵심 기능인 `phone_private`(관리자만 보는 연락처)가
**등록 화면에 입력칸이 없어서 값을 넣을 방법이 없습니다.**
같은 이유로 `email`, `is_visible`(노출 여부), `sort_order`(순서)도 입력칸이 없습니다.

**기본값 제안:** 최소한 `phone_private` 입력칸은 추가 (설계서에 있는 기능)

### ③ 줌 접속정보 컬럼 4개

`posters` 테이블의 `zoom_link`, `zoom_id`, `zoom_pw`, `zoom_note` 는
**발주처 원본 SQL에 없던 것을 전임 작업자가 추가**한 것입니다.
`savePoster()` 가 이 값을 저장하려 하는데 컬럼이 없어 에러가 날 상황이었기 때문입니다.
현재 값은 전부 비어 있고 화면에서도 숨김 상태입니다.

**기본값 제안:** 그대로 유지 (안 쓰면 그만, 나중에 지우기 쉬움)

> ⚠️ 유지 시 `posters` 는 전체 공개 조회 테이블이라 **줌 비밀번호가 비로그인
> 방문자에게 노출**됩니다. 실제로 쓸 거면 별도 처리 필요.

## 4. 작업 A — 저장·삭제 연결 (6군데)

**어려운 부분은 이미 만들어져 있습니다.** `js/db.js` 에 저장 함수가 전부 작성·검증된
상태입니다. **`index.html` 의 기존 함수가 그걸 호출하도록 바꿔 끼우는 일**입니다.

📌 **이렇게 말하세요:**

> **"인수인계서 4장대로 saveInstructor() 하나만 먼저 연결해줘. 검증하고 나머지 할 거야."**

| 함수 (`index.html`) | 호출할 것 (`js/db.js`) |
|---|---|
| `saveInstructor()` | `PickDB.saveInstructor(obj, editingId)` |
| `deleteInstructor()` | `PickDB.deleteInstructor(id)` |
| `savePoster()` | `PickDB.savePoster(obj, editingPosterId)` |
| `deletePoster()` | `PickDB.deletePoster(id)` |
| `saveTopAds()` | `PickDB.saveTopAds(list)` |
| `saveBanners()` | `PickDB.saveBanners(list)` |

### 클로드 참고용 — 교체 방식

동기 코드를 비동기로 바꾸는 작업입니다. 함수에 `async` 를 붙이고, 저장 후
DB에서 다시 읽어 화면을 갱신합니다. `index.html` 에 이미 만들어둔
**`loadFromDB()`** 와 **`renderAll()`** 을 쓰면 됩니다.

기존:
```javascript
if (editingId) {
    const idx = instructors.findIndex(i => i.id === editingId);
    if (idx > -1) { Object.assign(instructors[idx], newData); alert("수정되었습니다!"); }
} else {
    newData.id = ...;
    instructors.unshift(newData); alert("등록되었습니다!");
}
cancelAdminForm(); renderFilters(); setTagFilter('all');
```

교체 후:
```javascript
const btn = document.getElementById('admin-submit-btn');
btn.disabled = true;                       // 중복 저장 방지
try {
    await PickDB.saveInstructor(newData, editingId);
    await loadFromDB();                    // DB에서 다시 읽기
    renderAll();                           // 화면 즉시 갱신
    alert(editingId ? "수정되었습니다!" : "등록되었습니다!");
    cancelAdminForm();
} catch (e) {
    alert("저장에 실패했습니다.\n" + (e.message || ''));
} finally {
    btn.disabled = false;
}
```

**반드시 지킬 것**

- 기존 코드는 **실패해도 무조건 "등록되었습니다"** 를 띄웁니다. 실패 처리를 꼭 넣으세요.
- 저장 중 버튼을 잠그지 않으면 **중복 등록**됩니다.
- 저장 후 `loadFromDB()` + `renderAll()` 을 호출해야 **화면에 즉시 반영**됩니다.
- `saveInstructor` 는 영상 3개를 `instructor_videos` 에 **통째로 교체**합니다 (`js/db.js` 참고).
- 삭제는 `js/config.js` 의 `SOFT_DELETE: true` 라 **숨김 처리**가 기본입니다. 설계서 지침입니다.

## 5. 작업 B — 파일 업로드 연결 (11군데)

전부 `URL.createObjectURL`(새로고침하면 사라지는 임시 미리보기)로 되어 있습니다.
이걸 **`PickUpload.uploadFromInput(input, '폴더명')`** 으로 교체하면
Supabase Storage에 자동 저장됩니다.

📌 **이렇게 말하세요:**

> **"인수인계서 5장대로 강사 사진 업로드 하나만 먼저 연결해줘."**

| 대상 | 저장 폴더 |
|---|---|
| 강사 사진 | `instructors` |
| 강사 프로필 파일 | `profiles` |
| 영상 썸네일 3개 | `instructors` |
| 공고 포스터 | `posters` |
| 공고 약도 이미지 | `maps` |
| 상단광고 PC·모바일 이미지 | `ads` |
| 배너 PC·모바일 이미지·영상 | `banners` |

### 클로드 참고용 — 교체 방식

기존:
```javascript
if (photoInput.files[0]) newData.photo = URL.createObjectURL(photoInput.files[0]);
```

교체 후:
```javascript
const uploaded = await PickUpload.uploadFromInput(photoInput, 'instructors');
if (uploaded) newData.photo = uploaded;      // 파일 안 골랐으면 기존 사진 유지
```

**반드시 지킬 것**

- `uploadFromInput` 은 파일이 없으면 **빈 문자열**을 반환합니다.
  수정 시 새 파일을 안 고르면 **기존 사진이 지워지지 않도록** 위처럼 `if` 로 감싸세요.
- 용량 제한이 걸려 있습니다 (`js/upload.js`) — **이미지 5MB / 영상 20MB / 파일 20MB**.
  초과하면 에러를 던집니다.
- 업로드는 저장보다 오래 걸립니다. **진행 표시가 없으면 사용자가 버튼을 다시 누릅니다.**
- 파일 교체 시 이전 파일 정리는 `PickUpload.removeByUrl(oldUrl)` 을 쓰세요.
  외부 URL(`i.ibb.co` 등)은 자동으로 무시합니다.
- **영상 썸네일만 예외** — URL 직접 입력칸이 따로 있어 그게 1순위, 파일 업로드가 2순위입니다.

## 8. 알아둘 함정

**① 로그인해야 저장됩니다**
저장 시 `42501` 에러가 나면 **고장이 아니라 로그인이 안 된 상태**입니다.
서버 권한(RLS)이 정상 작동하고 있다는 뜻입니다.

**② 이용자 화면은 `instructors_public` 뷰로 조회해야 합니다**
`instructors` 본체에는 관리자 전용 연락처(`phone_private`)가 있습니다.
공개 뷰는 그 컬럼이 물리적으로 빠져 있어 코드가 잘못돼도 유출되지 않습니다.
**관리자 화면일 때만 본체를 조회합니다.** 이미 그렇게 구현돼 있으니 유지하세요.

**③ 비밀키를 코드에 넣지 마세요**
`js/config.js` 의 키 3개는 브라우저 공개용이라 커밋해도 됩니다.
Supabase `service_role` / `sb_secret_` 키는 **RLS를 전부 무시**하므로 절대 쓰면 안 됩니다.

**④ 기존 사진들은 외부 사이트에 있습니다**
강사 사진 21장·포스터·광고가 `i.ibb.co`(무료 이미지 호스팅)에 있습니다.
발주처가 화면 제작 시 임시로 올린 것으로, **서비스가 중단되면 사진이 사라집니다.**
업로드 기능을 만들어도 **기존 사진은 자동으로 안 옮겨갑니다.**
이관은 별도 작업이며, **발주처 지시 없이 진행하지 마세요.**

**⑤ 배포에서 내부 자료가 빠지는지 확인**
`.vercelignore` 로 `docs/ tools/ db/` 를 막아뒀습니다. 발주처 요청서·설계서·DB 구조가
공개 URL로 노출되면 안 됩니다. 새 폴더를 만들면 이 목록을 확인하세요.

**⑥ Tailwind CDN 사용 중**
콘솔에 프로덕션 경고가 뜹니다. 동작에는 문제없습니다.
